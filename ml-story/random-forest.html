جنگل تصادفی (Random Forest)

صدها درختِ کمی متفاوت، که با هم رأی می‌دهند. اول تصویر کلی، بعد کم‌کم جزئیات.

تصویر بزرگ

یک درختِ تصمیم یک مشکلِ بزرگ دارد: ناپایدار است. داده کمی عوض شود، درختِ کاملاً متفاوتی ساخته می‌شود، و زود بیش‌برازش می‌کند.

ایده‌ی جنگل تصادفی: به‌جای یک درخت، صدها درخت بساز. هر کدام را کمی متفاوت بساز (با تکه‌ی متفاوتی از داده و ویژگی‌ها). بعد از همه بپرس و رأیِ اکثریت (یا میانگین) را جواب بده.

اشتباه‌های تصادفیِ هر درخت با هم خنثی می‌شوند؛ چیزی که همه‌ی درخت‌ها درست فهمیده‌اند، می‌ماند.

چرا مهم است: روی داده‌ی جدولی یکی از قوی‌ترین مدل‌هاست، با تنظیماتِ پیش‌فرض هم خوب کار می‌کند، و تقریباً بیش‌برازش نمی‌کند. در مصاحبه تقریباً همیشه همراه با Boosting پرسیده می‌شود.

قدم ۱: هر درخت با نمونه‌ی متفاوتی از داده (Bagging)

از داده‌ی اصلی، به همان اندازه، با جایگذاری نمونه برمی‌داریم (Bootstrap). یعنی یک نمونه ممکن است چند بار انتخاب شود و یک نمونه اصلاً انتخاب نشود.

اگر فقط همین کار را بکنیم (بدون قدم ۲)، اسمش Bagging است (Bootstrap AGGregatING).

قدم ۲: هر سؤال فقط از بینِ چند ویژگیِ تصادفی

مشکلِ Bagging تنها: فرض کنید یک ویژگی خیلی قوی است (مثلاً درآمد). همه‌ی درخت‌ها سؤالِ اولشان را با همان می‌پرسند، پس درخت‌ها شبیهِ هم می‌شوند و اشتباه‌هایشان هم شبیه است. میانگین گرفتن از چیزهای شبیه، چیزی را خنثی نمی‌کند.

راه‌حل: در هر گره، درخت فقط از بینِ چند ویژگیِ تصادفی می‌تواند سؤال بپرسد (max_features). گاهی ویژگیِ قوی در دسترس نیست و درخت مجبور است از ویژگی‌های دیگر هم یاد بگیرد. درخت‌ها متفاوت‌تر می‌شوند.

دسته‌بندی

معمولاً \(\sqrt{p}\) ویژگی در هر گره (با ۱۰۰ ویژگی، ۱۰ تا).

رگرسیون

معمولاً \(p/3\) ویژگی، یا در scikit-learn همه‌ی ویژگی‌ها.

چرا متفاوت بودنِ درخت‌ها این‌قدر مهم است؟ (فرمول)

اگر \(B\) درخت داشته باشیم، هر کدام با واریانسِ \(\sigma^2\)، و هم‌بستگیِ بینِ دو درخت \(\rho\) باشد، واریانسِ میانگینشان:

\[ \text{Var} = \rho\,\sigma^2 + \frac{1 - \rho}{B}\,\sigma^2 \]

تکه‌ی دوم با درختِ بیشتر (\(B\) بزرگ) کم می‌شود. ولی تکه‌ی اول، \(\rho\,\sigma^2\)، با هیچ تعدادی از درخت کم نمی‌شود؛ فقط با کم کردنِ هم‌بستگیِ درخت‌ها. این دقیقاً کارِ قدم ۲ است.

مثال: σ² = ۱. اگر درخت‌ها کاملاً هم‌بسته باشند (ρ = ۱)، واریانس همیشه ۱ می‌ماند. اگر ρ = ۰٫۳ و ۱۰۰ درخت: ۰٫۳ + ۰٫۷/۱۰۰ ≈ ۰٫۳۱.

قدم ۳: رأی‌گیری

دسته‌بندی

هر درخت یک دسته می‌گوید؛ دسته‌ای که بیشترین رأی را دارد برنده است. سهمِ رأی‌ها (مثلاً ۷۰ از ۱۰۰ درخت) را می‌شود به‌عنوان احتمال گزارش کرد.

رگرسیون

میانگینِ عددهای همه‌ی درخت‌ها.

خودتان ببینید: تعدادِ درخت‌ها را زیاد کنید. هر درخت تا آخر رشد کرده (بیش‌برازش‌شده)، ولی جنگل مرزی آرام‌تر می‌کشد:

خوش‌حساببدحسابرنگِ زمینه = سهمِ رأیِ درخت‌ها

برای مقایسه: یک درختِ تنها که تا آخر رشد کرده، روی داده‌ی جدید ۷۵٪ درست است؛ جنگل با ۳۰ درخت یا بیشتر حدود ۷۹٪. سقفِ واقعی در این داده حدود ۸۸٪ است، چون ۱۲٪ برچسب‌ها عمداً به هم ریخته‌اند.

یک سنجشِ رایگان: Out-of-Bag

یادتان هست هر درخت حدود ۳۷٪ داده را ندیده؟ برای هر نمونه، فقط از درخت‌هایی که آن را ندیده‌اند بپرس. این پیش‌بینی برای آن نمونه مثلِ پیش‌بینی روی داده‌ی جدید است.

دقتِ همه‌ی این پیش‌بینی‌ها را OOB Score می‌گویند: یک تخمین از دقت روی داده‌ی جدید، بدون کنار گذاشتنِ داده‌ی سنجش.

در scikit-learn: RandomForestClassifier(oob_score=True) و بعد model.oob_score_.

تنظیم‌های مهم

n_estimators

تعدادِ درخت‌ها. بیشتر تقریباً همیشه بهتر یا برابر است (بیش‌برازش نمی‌کند)، فقط کندتر. معمولاً چند صد.

max_features

چند ویژگی در هر گره. کمتر ← درخت‌ها متفاوت‌تر (واریانسِ کمتر) ولی هر درخت ضعیف‌تر. مهم‌ترین تنظیم.

max_depth / min_samples_leaf

عمقِ هر درخت. معمولاً درخت‌ها را عمیق می‌گذارند و می‌گذارند میانگین‌گیری کارِ کنترلِ بیش‌برازش را بکند؛ ولی با داده‌ی خیلی پرنویز، محدود کردن کمک می‌کند.

خوبی‌ها و بدی‌ها

خوبی‌ها

  • با تنظیماتِ پیش‌فرض هم خیلی خوب است.
  • خیلی کمتر از یک درخت بیش‌برازش می‌کند.
  • هم‌مقیاس کردنِ ویژگی‌ها لازم نیست.
  • درخت‌ها مستقل‌اند، پس موازی ساخته می‌شوند (سریع روی چند هسته).
  • OOB Score و اهمیتِ ویژگی‌ها را مجانی می‌دهد.

بدی‌ها

  • صدها درخت را نمی‌شود مثلِ یک درخت کشید و توضیح داد.
  • مدلِ بزرگ و پیش‌بینیِ کندتر از یک درخت.
  • بیرون از محدوده‌ی داده پیش‌بینی نمی‌کند (مثلِ درخت).
  • معمولاً کمی ضعیف‌تر از Boosting خوب‌تنظیم‌شده.

جنگل تصادفی در برابر Boosting

جنگل تصادفی (Bagging)

  • درخت‌ها هم‌زمان و مستقل ساخته می‌شوند.
  • هر درخت عمیق و قوی ولی پرنوسان است.
  • میانگین‌گیری واریانس را کم می‌کند.
  • تنظیمِ کم لازم دارد.

Boosting (مثلاً XGBoost، LightGBM)

  • درخت‌ها یکی پس از دیگری؛ هر درخت اشتباه‌های قبلی‌ها را درست می‌کند.
  • هر درخت کم‌عمق و ضعیف است.
  • جمع کردنِ درخت‌ها بایاس را کم می‌کند.
  • معمولاً دقیق‌تر، ولی به تنظیم حساس‌تر و راحت‌تر بیش‌برازش می‌کند.

Boosting موضوعِ صفحه‌ی بعد است.

کد

جنگل از صفر (با درختِ scikit-learn به‌عنوانِ درختِ پایه):

import numpy as np
from sklearn.tree import DecisionTreeClassifier

def fit_forest(X, y, n_trees=100, max_features="sqrt", seed=0):
    rng = np.random.default_rng(seed)
    trees = []
    for _ in range(n_trees):
        idx = rng.integers(0, len(X), len(X))        # bootstrap: sample with replacement
        t = DecisionTreeClassifier(max_features=max_features,
                                   random_state=int(rng.integers(1e9)))
        trees.append(t.fit(X[idx], y[idx]))
    return trees

def predict_forest(trees, X):
    votes = np.mean([t.predict(X) for t in trees], axis=0)   # share of trees voting 1
    return (votes >= 0.5).astype(int)

How does a random forest work?

It trains many decision trees and combines them. Two sources of randomness make the trees different: (1) each tree is trained on a bootstrap sample (sampling rows with replacement); (2) at each split, only a random subset of features is considered. Prediction is a majority vote (classification) or an average (regression). Each tree overfits in its own way; averaging cancels much of that noise.

What is bagging, and why does it reduce variance?

Bagging (bootstrap aggregating) trains the same model on many bootstrap samples and averages them. If each model has variance \(\sigma^2\) and the pairwise correlation is \(\rho\), the average of \(B\) models has variance

\[ \rho\,\sigma^2 + \frac{1-\rho}{B}\,\sigma^2 \]

More models shrink the second term toward 0. The bias stays about the same as one model, so bagging works best with low-bias, high-variance models such as deep trees.

What is the difference between bagging and a random forest? Why does max_features matter?

A random forest is bagging plus feature subsampling at every split. In the variance formula, more trees only shrink the second term; the first term \(\rho\sigma^2\) can only shrink by lowering \(\rho\). If one feature is very strong, all bagged trees split on it first and become correlated. Restricting each split to a random subset (typically \(\sqrt{p}\) for classification, about \(p/3\) for regression) decorrelates the trees. Smaller max_features means less correlation but weaker individual trees: it is the main hyperparameter to tune.

What is the out-of-bag (OOB) error?

Each bootstrap sample leaves out about \((1 - 1/n)^n \approx e^{-1} \approx 37\%\) of the rows. For each row, predict using only the trees that did not see it, and compare with the true label. The resulting accuracy (or error) is an almost unbiased estimate of test performance, obtained without a separate validation set. Useful when data is scarce.

Can a random forest overfit? Does adding more trees cause overfitting?

Adding trees does not cause overfitting: the error converges as \(B\) grows; more trees only cost time and memory. But the forest can still overfit if each tree memorises noise and the trees are highly correlated, e.g. very noisy data with a few strong features. Then limit depth or min_samples_leaf, or lower max_features.

Random forest vs gradient boosting: what is the difference, and when would you use each?

Random forest: trees built independently and in parallel on bootstrap samples; deep trees; averaging reduces variance; robust with default settings and hard to overfit by adding trees.

Gradient boosting: trees built sequentially, each fitting the errors (gradients) of the current ensemble; shallow trees; summing reduces bias; usually more accurate when tuned, but sensitive to learning rate, number of trees and depth, and can overfit if trained too long.

Rule of thumb: random forest for a strong, low-effort baseline; gradient boosting (XGBoost, LightGBM, CatBoost) when you need the best accuracy and can tune it.

How is feature importance computed in a random forest? What are its problems?

Mean decrease in impurity: average, over all trees, the impurity reduction from splits on each feature. It is fast but biased toward features with many unique values and is computed on training data. With correlated features, importance is split between them, so each looks less important. Permutation importance on held-out data (shuffle a feature and measure the score drop) is more reliable; SHAP values give per-prediction explanations.

Does a random forest need feature scaling? Can it extrapolate?

No scaling: splits depend only on the order of values. No extrapolation: every prediction is an average of training targets in some leaves, so for inputs beyond the training range it predicts roughly the value at the edge of the data. For trends that continue past the data (e.g. prices over time), a linear model or added trend features may be needed.

How would you handle class imbalance with a random forest?

Use class_weight="balanced" or "balanced_subsample" (weights recomputed per bootstrap sample), balanced bootstrap sampling (undersample the majority class in each tree), tune the decision threshold on the vote share, and evaluate with precision, recall, F1 or PR-AUC instead of accuracy.

What are the main hyperparameters and how do you tune them?

n_estimators: increase until the OOB or validation score stops improving (hundreds). max_features: the most important; try \(\sqrt{p}\), \(\log_2 p\), and fractions like 0.3 to 0.5. min_samples_leaf / max_depth: raise or limit for noisy data. Tune with OOB score or cross-validated random search.
