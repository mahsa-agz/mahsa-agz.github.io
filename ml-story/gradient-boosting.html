گرادیان بوستینگ (Gradient Boosting)

درخت‌هایی که یکی پس از دیگری، اشتباهِ قبلی‌ها را درست می‌کنند. اول تصویر کلی، بعد کم‌کم جزئیات.

تصویر بزرگ

جنگل تصادفی صدها درختِ مستقل می‌سازد و میانگین می‌گیرد. Boosting برعکس، درخت‌ها را پشتِ سرِ هم می‌سازد:

  1. یک حدسِ ساده بزن (مثلاً میانگینِ قیمت‌ها).
  2. ببین کجا اشتباه کردی.
  3. یک درختِ کوچک بساز که همین اشتباه‌ها را پیش‌بینی کند.
  4. کمی از آن را به حدست اضافه کن، و از قدمِ ۲ تکرار کن.
هر درخت به‌تنهایی ضعیف است. ولی هر کدام یک تکه از اشتباهِ باقی‌مانده را درست می‌کند، و جمعِ صدها درخت یک مدلِ خیلی دقیق می‌سازد.

چرا مهم است: روی داده‌ی جدولی (جدول‌های مشتری، تراکنش، تبلیغ) معمولاً دقیق‌ترین مدل است. XGBoost، LightGBM و CatBoost در صنعت و مسابقه‌های Kaggle همه‌جا هستند، و تقریباً در هر مصاحبه‌ی ML پرسیده می‌شوند.

خودتان ببینید

داده‌ی پرنویز با یک الگوی موج‌دار. هر درخت فقط دو سؤال می‌پرسد (عمق ۲). تعدادِ درخت‌ها را زیاد کنید:

چند درختِ اول

مدل از یک خطِ صاف (میانگین) کم‌کم شکلِ موج را می‌گیرد. هر دو خطا تند پایین می‌آیند.

درخت‌های خیلی زیاد

خطای آموزش هنوز کم می‌شود (مدل نویز را حفظ می‌کند)، ولی خطای داده‌ی جدید دیگر کم نمی‌شود و کمی بالا می‌رود. برخلافِ جنگل تصادفی، Boosting با درختِ زیادی بیش‌برازش می‌کند.

نرخ یادگیری: قدم‌های کوچک‌تر، مدلِ بهتر

به‌جای این‌که کلِ پیشنهادِ هر درخت را قبول کنیم، فقط یک تکه‌ی کوچک (\(\eta\)) را اضافه می‌کنیم (Shrinkage):

\[ F_m(x) = F_{m-1}(x) + \eta \cdot h_m(x) \]
  • \(F_{m-1}\): مدل تا قبل از این درخت
  • \(h_m\): درختِ جدید، که residualها را پیش‌بینی می‌کند
  • \(\eta\): نرخ یادگیری، معمولاً ۰٫۰۱ تا ۰٫۳

نرخِ بزرگ (مثلاً ۱)

با چند درخت سریع خوب می‌شود، ولی هر درخت نویزِ خودش را کامل وارد می‌کند. زود به بهترین حالت می‌رسد و زود هم خراب می‌شود.

نرخِ کوچک (مثلاً ۰٫۱)

درختِ بیشتری لازم دارد، ولی هر درخت کمی اثر دارد، پس نویز میانگین گرفته می‌شود و مدل معمولاً روی داده‌ی جدید کمی بهتر است.

در شکلِ بالا امتحان کنید: با نرخِ ۱، بهترین خطای داده‌ی جدید با حدود ۴ درخت است و بعدش سریع بدتر می‌شود؛ با نرخِ ۰٫۱ با حدود ۶۰ درخت، و منحنی خیلی صاف‌تر است، پس اگر تعدادِ درخت را کمی اشتباه انتخاب کنید، ضررش کم است. در این داده‌ی کوچک بهترین خطاها نزدیکِ هم‌اند؛ روی داده‌های بزرگِ واقعی، نرخِ کوچک معمولاً کمی هم دقیق‌تر است. قانونِ رایج: نرخ را کوچک بگذار و تعدادِ درخت را با توقفِ زودهنگام (Early Stopping) پیدا کن: آموزش را وقتی خطای داده‌ی سنجش چند دور بهتر نشد، متوقف کن.

چرا «گرادیان»؟

با تابع خطای MSE، residual دقیقاً همان منفیِ گرادیان است:

\[ L = \tfrac{1}{2}(y - F)^2 \quad\Rightarrow\quad -\frac{\partial L}{\partial F} = y - F = \text{residual} \]

پس «درخت روی residualها» یعنی «درخت روی منفیِ گرادیان». این‌جا گرادیان کاهشی روی وزن‌ها نیست، روی خودِ پیش‌بینی‌ها است: هر درخت یک قدم در جهتی است که خطا را کم می‌کند.

مزیتِ این دید: برای هر تابع خطای مشتق‌پذیر کار می‌کند، نه فقط MSE:

رگرسیون با MSE

منفیِ گرادیان = \(y - F\) (همان residual)

دسته‌بندی با Log Loss

منفیِ گرادیان = \(y - p\)؛ برچسب منهای احتمالِ پیش‌بینی‌شده (همان فرمولِ رگرسیون لجستیک). خروجیِ درخت‌ها جمع می‌شود و از سیگموید رد می‌شود.

رگرسیون با Huber یا MAE

برای داده‌ی پرت؛ فقط فرمولِ گرادیان عوض می‌شود.

Boosting در برابر Bagging

جنگل تصادفی (Bagging)

  • درخت‌ها مستقل و هم‌زمان.
  • درخت‌ها عمیق؛ هر کدام دقیق ولی پرنوسان.
  • میانگین‌گیری ← واریانس کم می‌شود.
  • درختِ بیشتر ← بیش‌برازش نمی‌کند.
  • با تنظیمِ پیش‌فرض خوب است.

گرادیان بوستینگ

  • درخت‌ها پشتِ سرِ هم؛ هر کدام به قبلی وابسته.
  • درخت‌ها کم‌عمق (معمولاً ۳ تا ۸ طبقه)؛ هر کدام ضعیف.
  • جمع کردن ← بایاس کم می‌شود.
  • درختِ زیادی ← بیش‌برازش؛ توقفِ زودهنگام لازم است.
  • معمولاً دقیق‌تر، ولی تنظیمِ بیشتری می‌خواهد.
AdaBoost: نسخه‌ی قدیمی‌تر

AdaBoost (سال ۱۹۹۵) هم درخت‌ها را پشتِ سرِ هم می‌سازد، ولی به‌جای پیش‌بینیِ residual، وزنِ نمونه‌ها را عوض می‌کند: نمونه‌هایی که درختِ قبلی اشتباه دسته‌بندی کرده، وزنِ بیشتری می‌گیرند تا درختِ بعدی بیشتر به آن‌ها توجه کند. هر درخت هم بسته به دقتش یک وزن در رأیِ نهایی دارد. بعدها معلوم شد AdaBoost همان گرادیان بوستینگ با تابع خطای نمایی است.

XGBoost، LightGBM و CatBoost

هر سه همان گرادیان بوستینگ‌اند، با ترفندهایی برای سرعت و دقت:

تنظیم‌های مهم

learning_rate + n_estimators

با هم تنظیم می‌شوند: نرخ کوچک، درختِ بیشتر، با early stopping.

max_depth / num_leaves

پیچیدگیِ هر درخت. کم‌عمق (۳ تا ۸) معمولاً کافی است.

subsample / colsample

هر درخت فقط بخشی از سطرها یا ستون‌ها را ببیند (مثل جنگل تصادفی). بیش‌برازش را کم و سرعت را زیاد می‌کند.

min_child_weight / min_data_in_leaf

حداقلِ داده در هر برگ؛ جلوی برگ‌های ریز و حفظ کردنِ نویز را می‌گیرد.

lambda / alpha / gamma

جریمه‌ی L2 و L1 روی مقدارِ برگ‌ها، و جریمه برای هر برگِ اضافه (XGBoost).

کد

گرادیان بوستینگ از صفر (رگرسیون، با درختِ scikit-learn):

import numpy as np
from sklearn.tree import DecisionTreeRegressor

def fit_gb(X, y, n_trees=100, lr=0.1, depth=3):
    f0 = y.mean()
    F = np.full(len(y), f0)
    trees = []
    for _ in range(n_trees):
        residual = y - F                       # = negative gradient of MSE
        t = DecisionTreeRegressor(max_depth=depth).fit(X, residual)
        F += lr * t.predict(X)                 # small step toward lower error
        trees.append(t)
    return f0, trees

def predict_gb(f0, trees, X, lr=0.1):
    return f0 + lr * sum(t.predict(X) for t in trees)

سؤال‌های مصاحبه

How does gradient boosting work?

It builds an additive model one tree at a time. Start with a constant \(F_0\) (e.g. the mean). At step \(m\), compute the negative gradient of the loss for every training example (for MSE: the residual \(y - F_{m-1}(x)\)), fit a small tree \(h_m\) to it, and update \(F_m = F_{m-1} + \eta\, h_m\). Each tree corrects what the ensemble still gets wrong. Example: prices 300, 400, 600, 700; start at 500; after two depth-1 trees with \(\eta = 0.5\) the largest error drops from 200 to 87.5.

Why is it called "gradient" boosting?

Because each tree approximates the negative gradient of the loss with respect to the current predictions, i.e. it is gradient descent in function space. For \(L = \tfrac12(y-F)^2\), \(-\partial L/\partial F = y - F\), the residual. For log loss, it is \(y - p\). This makes the method work for any differentiable loss.

What is the difference between bagging (random forest) and boosting?

Bagging trains strong, deep models independently in parallel and averages them, which reduces variance; more trees never hurt. Boosting trains weak, shallow models sequentially, each fitting the errors of the previous ones, which reduces bias; too many rounds overfit, so it needs a learning rate and early stopping. Boosting is usually more accurate when tuned; random forest is more robust with defaults.

PracHub (bias-variance, bagging and boosting); Analytics Vidhya

What does the learning rate (shrinkage) do?

It scales each tree's contribution: \(F_m = F_{m-1} + \eta h_m\). Small \(\eta\) means each tree only nudges the model, so the noise of individual trees averages out and generalisation is usually better, at the cost of more trees. In the demo above, \(\eta = 1\) reaches its best test error at about 4 trees and then degrades quickly; \(\eta = 0.1\) needs about 60 trees but its curve is much flatter, so the exact number of trees matters less. Tune \(\eta\) and the number of trees together with early stopping on a validation set.

Can gradient boosting overfit? How do you prevent it?

Yes: with enough rounds it keeps reducing training error by fitting noise. Prevent it with early stopping, a small learning rate, shallow trees (max_depth, num_leaves), row and column subsampling, minimum samples per leaf, and L1/L2 regularisation on leaf values.

What does XGBoost do differently from plain gradient boosting?

(1) A regularised objective: \(\sum \text{loss} + \sum_{\text{trees}} \big(\gamma T + \tfrac12 \lambda \sum_j w_j^2\big)\), penalising the number of leaves \(T\) and large leaf values \(w_j\). (2) A second-order (Newton) step using both gradient and Hessian, which gives the optimal leaf value \(w_j = -G_j / (H_j + \lambda)\) and a closed-form split gain. (3) Engineering: sparsity-aware handling of missing values (a learned default direction), histogram/approximate split finding, parallel and cache-aware computation.

Analytics India Magazine (XGBoost interview questions)

XGBoost vs LightGBM vs CatBoost?

XGBoost: regularised objective, second-order steps, level-wise trees; a robust default. LightGBM: histogram binning, leaf-wise growth (split the leaf with the largest gain), GOSS and feature bundling; fastest on large data but can overfit small data, so limit num_leaves. CatBoost: native categorical handling with ordered target statistics and ordered boosting to avoid target leakage; symmetric trees; good results with little tuning. Accuracy is usually similar; choose by data size, categorical features and speed.

KDnuggets; Towards Data Science; PracHub (compare XGBoost and LightGBM)

AdaBoost vs gradient boosting?

AdaBoost reweights the training examples: misclassified examples get larger weights so the next weak learner focuses on them, and each learner gets a vote weight based on its accuracy. Gradient boosting instead fits each new learner to the negative gradient (the residuals for squared error). AdaBoost is equivalent to gradient boosting with the exponential loss, which makes it sensitive to outliers and label noise.

Why are boosting trees shallow while random forest trees are deep?

Random forest reduces variance by averaging, so each tree should have low bias (deep) even if its variance is high. Boosting reduces bias by adding trees, so each tree only needs to capture a little structure; shallow trees (stumps to depth 8) keep each step small and the variance low. Tree depth in boosting also controls the order of feature interactions the model can learn.

How does gradient boosting do classification?

The trees predict a score (log-odds) \(F(x)\); the probability is \(p = \sigma(F(x))\). Each round fits a tree to the negative gradient of log loss, \(y - p\), and (in XGBoost/LightGBM) uses the Hessian \(p(1-p)\) to set leaf values. For \(K\) classes it fits \(K\) trees per round and uses softmax.
