ماشین بردار پشتیبان (Support Vector Machine, SVM)

بینِ دو دسته، پهن‌ترین خیابانِ ممکن را می‌کشیم. اول تصویر کلی، بعد کم‌کم جزئیات.

تصویر بزرگ

دو دسته داده داریم و می‌خواهیم با یک خط جدایشان کنیم. معمولاً خط‌های زیادی این کار را می‌کنند. کدام بهتر است؟

جوابِ SVM:

  1. خطی را انتخاب کن که از هر دو دسته تا جای ممکن دور باشد.
  2. دو طرفِ خط یک «خیابان» خالی می‌ماند. SVM پهن‌ترین خیابان را پیدا می‌کند.
  3. فقط نقطه‌هایی که لبه‌ی خیابان هستند مهم‌اند. به آن‌ها بردار پشتیبان (Support Vector) می‌گویند.
SVM خطی را می‌خواهد که بیشترین فاصله (Margin) را تا نزدیک‌ترین نقطه‌های هر دسته داشته باشد. خیابانِ پهن‌تر یعنی مدل روی داده‌ی جدید کمتر اشتباه می‌کند.

چرا مهم است:

  • قبل از یادگیریِ عمیق، روی خیلی از مسئله‌ها بهترین مدل بود.
  • هنوز روی داده‌ی کوچک و متوسط و داده‌ی پرُبُعد (مثلاً متن) خیلی خوب کار می‌کند.
  • در مصاحبه زیاد پرسیده می‌شود: حاشیه، بردار پشتیبان، پارامتر C، Hinge Loss، ترفند کرنل.

مثالِ این صفحه: فیلترِ اسپم با دو ویژگی:

  • \(x_1\): تعدادِ لینک‌های ایمیل
  • \(x_2\): تعدادِ کلمه‌های تبلیغاتی (مثل «رایگان»، «جایزه»)

۱۴ ایمیل داریم: ۷ ایمیلِ عادی (ham، برچسب \(-1\)، آبی) و ۷ اسپم (برچسب \(+1\)، نارنجی).

پهن‌ترین خیابان

هر چهار خطِ زیر همه‌ی ۱۴ ایمیل را درست جدا می‌کنند. ولی فاصله‌شان تا نزدیک‌ترین ایمیل خیلی فرق دارد:

سه خطِ دلخواه

  • خطِ ۱ (\(x_1 = 4.5\)): نزدیک‌ترین ایمیل در فاصله‌ی ۰٫۵۰
  • خطِ ۲ (\(x_1 + x_2 = 10.5\)): فاصله‌ی ۰٫۳۵
  • خطِ ۳ (\(x_1 + 0.3x_2 = 5.2\)): فاصله‌ی ۰٫۸۶

خطِ SVM

  • فاصله تا نزدیک‌ترین ایمیل: ۲٫۰۳
  • پهنای کلِ خیابان: ۴٫۰۶
  • سه ایمیلِ حلقه‌دار روی لبه‌ی خیابان‌اند: بردارهای پشتیبان.
hamاسپمخطِ SVM و لبه‌های خیابان

چرا خیابانِ پهن بهتر است؟ ایمیل‌های جدید دقیقاً روی ایمیل‌های قدیمی نمی‌افتند؛ کمی این‌طرف و آن‌طرف‌اند. خطِ ۲ فقط ۰٫۳۵ با یک اسپم فاصله دارد. یک اسپمِ جدید که کمی شبیهِ ham باشد، از خط رد می‌شود و اشتباه دسته‌بندی می‌شود. خطِ SVM تا ۲٫۰۳ واحد جا برای این لرزش دارد.

بردارهای پشتیبان: فقط نزدیک‌ترین نقطه‌ها مهم‌اند

خطِ SVM را فقط نقطه‌های لبه‌ی خیابان می‌سازند. بقیه‌ی نقطه‌ها هر جا باشند (به شرطی که وارد خیابان نشوند)، خط عوض نمی‌شود. خودتان امتحان کنید: نقطه‌ها را با ماوس یا انگشت بکشید.

hamاسپمخط و لبه‌های خیابان؛ حلقه = بردار پشتیبان

جابه‌جا کردنِ یک نقطه‌ی دور

اسپمِ (۹، ۸) را به (۹٫۵، ۶) می‌بریم. خط و پهنای خیابان (۴٫۰۶) هیچ تغییری نمی‌کنند. این نقطه در ساختنِ خط نقشی ندارد.

جابه‌جا کردنِ یک بردار پشتیبان

اسپمِ (۶، ۵) را به (۵٫۵، ۴٫۵) می‌بریم، کمی به سمتِ hamها. خط می‌چرخد و خیابان از ۴٫۰۶ به ۳٫۳۶ باریک می‌شود.

اگر نقطه‌ای را به آن طرفِ دسته‌ی دیگر بکشید، دیگر هیچ خطی همه را جدا نمی‌کند و «حاشیه‌ی سخت» جواب ندارد. راهِ حلش «حاشیه‌ی نرم» است که پایین‌تر می‌آید.

نتیجه‌ی مهم: مدلِ آموزش‌دیده فقط بردارهای پشتیبان را لازم دارد. این‌جا از ۱۴ نقطه فقط ۳ تا.

ریاضیِ خیابان

خط را با یک بردارِ وزن \(w\) و یک عددِ \(b\) می‌نویسیم:

\[ f(x) = w \cdot x + b = w_1 x_1 + w_2 x_2 + b \qquad \hat{y} = \operatorname{sign}\big(f(x)\big) \]
  • \(x\): ویژگی‌های یک نمونه
  • \(w\): بردارِ وزن (عمود بر خط)
  • \(b\): عرض از مبدأ (bias)
  • \(f(x) = 0\): خودِ خط
  • \(f(x) = \pm 1\): دو لبه‌ی خیابان
  • \(\hat{y}\): پیش‌بینی، \(+1\) یا \(-1\)

فاصله‌ی هر نقطه تا خط برابرِ \(|f(x)| / \lVert w \rVert\) است. لبه‌ها جایی‌اند که \(f = \pm 1\)، پس:

\[ \text{margin width} = \frac{2}{\lVert w \rVert} \]

خیابانِ پهن‌تر یعنی \(\lVert w \rVert\) کوچک‌تر. پس SVM این مسئله را حل می‌کند (حاشیه‌ی سخت):

\[ \min_{w,\,b} \ \tfrac{1}{2}\lVert w \rVert^2 \quad \text{subject to} \quad y_i\,(w \cdot x_i + b) \ge 1 \ \ \text{for every } i \]
  • \(y_i\): برچسبِ نمونه‌ی \(i\)، \(+1\) یا \(-1\)
  • \(y_i f(x_i) \ge 1\): هر نقطه درست است و بیرونِ خیابان
  • \(\tfrac12\lVert w\rVert^2\): کوچکش کن تا خیابان پهن شود

با عدد، برای ۱۴ ایمیلِ ما جواب این است:

\[ w = \left(\tfrac{5}{13},\ \tfrac{4}{13}\right) \approx (0.385,\ 0.308), \qquad b = -\tfrac{37}{13} \approx -2.846 \]
  • \(\lVert w \rVert = \sqrt{41}/13 \approx 0.493\)، پس پهنای خیابان \(= 2 / 0.493 \approx 4.06\).
  • بردار پشتیبانِ اسپمِ (۶، ۵): \(f = 0.385 \cdot 6 + 0.308 \cdot 5 - 2.846 = 1.00\). دقیقاً روی لبه.
  • ham‌های (۲، ۳٫۵) و (۴، ۱): \(f = -1.00\). روی لبه‌ی دیگر.
  • ایمیلِ جدیدِ (۷، ۳): \(f = 0.769\). مثبت، پس اسپم؛ ولی کمتر از ۱، یعنی داخلِ خیابان و نزدیکِ مرز.
  • ایمیلِ جدیدِ (۲، ۲): \(f = -1.462\). منفی، پس ham، و دور از مرز.
فرمِ دوگان: چرا فقط بردارهای پشتیبان مهم‌اند؟

با ضریب‌های لاگرانژ، جوابِ SVM را می‌شود این‌طور نوشت:

\[ w = \sum_i \alpha_i\, y_i\, x_i, \qquad f(x) = \sum_i \alpha_i\, y_i\, (x_i \cdot x) + b, \qquad 0 \le \alpha_i \le C \]

برای نقطه‌هایی که بیرونِ خیابان‌اند، \(\alpha_i = 0\). فقط بردارهای پشتیبان \(\alpha_i > 0\) دارند. پس جابه‌جا کردنِ یک نقطه‌ی دور، هیچ جمله‌ای از این جمع را عوض نمی‌کند.

نکته‌ی دوم: در این فرم داده فقط به شکلِ ضربِ داخلیِ \(x_i \cdot x\) آمده. همین در بخشِ کرنل مهم می‌شود.

الگوریتمِ معمولِ حلِ این فرم SMO است (در libsvm و SVC). شکل‌های این صفحه هم با همین روش در مرورگر حل می‌شوند، و جواب‌ها با scikit-learn یکی است.

حاشیه‌ی سخت و نرم، و پارامتر C

داده‌ی واقعی تمیز نیست. دو ایمیلِ عجیب به مثال اضافه می‌کنیم:

  • یک اسپم با لینک و کلمه‌ی تبلیغاتیِ کم: (۴٫۶، ۲٫۶)
  • یک ham با کلمه‌های تبلیغاتیِ زیاد: (۳٫۸، ۵٫۶)

هنوز می‌شود همه را با یک خط جدا کرد، ولی خیابان فقط ۰٫۶۷ پهنا دارد. شاید بهتر باشد این دو را «اشتباه» قبول کنیم و خیابانِ پهن‌تری داشته باشیم.

حاشیه‌ی سخت (Hard Margin)

هیچ نقطه‌ای حق ندارد داخلِ خیابان یا آن طرفِ خط باشد. اگر داده جداشدنی نباشد، اصلاً جواب ندارد. یک نقطه‌ی پرت می‌تواند خط را خیلی جابه‌جا کند.

حاشیه‌ی نرم (Soft Margin)

نقطه‌ها می‌توانند وارد خیابان شوند یا حتی اشتباه شوند، ولی برای هر کدام جریمه می‌دهیم. C تعیین می‌کند این جریمه چقدر سنگین است.

\[ \min_{w,\,b,\,\xi} \ \tfrac{1}{2}\lVert w \rVert^2 + C \sum_i \xi_i \quad \text{subject to} \quad y_i\,(w \cdot x_i + b) \ge 1 - \xi_i,\ \ \xi_i \ge 0 \]
  • \(\xi_i\): مقدارِ تخلفِ نقطه‌ی \(i\) (slack)
  • \(\xi_i = 0\): بیرونِ خیابان، درست
  • \(0 < \xi_i \le 1\): داخلِ خیابان، هنوز درست
  • \(\xi_i > 1\): آن طرفِ خط، اشتباه
  • \(C\): وزنِ جریمه‌ی تخلف‌ها

C کوچک (۰٫۰۱)

تخلف ارزان است. خیابان پهن می‌شود (۷٫۷۵) و ۲ ایمیل اشتباه دسته‌بندی می‌شوند. ۱۲ نقطه از ۱۶ داخلِ خیابان یا اشتباه‌اند و ۱۴ بردار پشتیبان داریم. مدل ساده و محتاط است؛ ممکن است کم‌برازش کند.

C بزرگ (۱۰۰)

تخلف خیلی گران است. مدل همه را درست می‌کند (۰ اشتباه)، ولی خیابان فقط ۰٫۶۷ است و خط به‌خاطرِ دو ایمیلِ عجیب کج شده. فقط ۳ بردار پشتیبان. ممکن است بیش‌برازش کند.

C معکوسِ قدرتِ منظم‌سازی است: C کوچک ← منظم‌سازیِ قوی، خیابانِ پهن. C بزرگ ← منظم‌سازیِ ضعیف، خیابانِ باریک. بهترین C را با اعتبارسنجیِ متقابل پیدا کنید (مثلاً بین ۰٫۰۱ تا ۱۰۰ با ضریبِ ۱۰).

Hinge Loss: تابعِ خطای SVM

قیدِ \(\xi_i \ge 1 - y_i f(x_i)\) و \(\xi_i \ge 0\) یعنی کوچک‌ترین \(\xi_i\) همین است:

\[ \xi_i = \max\big(0,\ 1 - y_i f(x_i)\big) \]

پس SVM یعنی کمینه کردنِ این تابع، بدونِ هیچ قیدی:

\[ J(w, b) = \tfrac{1}{2}\lVert w \rVert^2 + C \sum_i \max\big(0,\ 1 - y_i (w \cdot x_i + b)\big) \]
  • \(y_i f(x_i)\): «امتیازِ درستی»؛ مثبت یعنی درست
  • \(\max(0, \cdot)\): Hinge Loss
  • \(\tfrac12\lVert w\rVert^2\): جریمه‌ی L2 روی وزن‌ها

ترفند کرنل: وقتی یک خط کافی نیست

گاهی داده با هیچ خطی جدا نمی‌شود. مثالِ یک‌بعدی: نقطه‌های آبی در وسط (−۱ تا ۱)، نقطه‌های نارنجی در دو طرف (±۲٫۵ و ±۳). روی خطِ اعداد، هیچ نقطه‌ی برشی این دو را جدا نمی‌کند.

راه حل: یک ویژگیِ جدید بساز، \(x^2\). حالا هر نقطه دو عدد دارد: \((x, x^2)\). آبی‌ها \(x^2 \le 1\) دارند و نارنجی‌ها \(x^2 \ge 6.25\). یک خطِ افقی (مثلاً \(x^2 = 3.6\)) جدایشان می‌کند.

قبل: یک بُعد، جدا نمی‌شود

بعد: با \(x^2\)، یک خط جدا می‌کند

خطِ صاف در فضای \((x, x^2)\)، در فضای اصلی یعنی دو نقطه‌ی برش: \(x = \pm\sqrt{3.6} \approx \pm 1.9\). یک مرزِ غیرخطی با یک مدلِ خطی ساختیم.

ترفند کجاست؟ SVM (در فرمِ دوگان) فقط ضربِ داخلیِ نقطه‌ها را لازم دارد. یک کرنل \(K(x, z)\) همین ضربِ داخلی را در فضای جدید مستقیم حساب می‌کند، بدونِ این‌که نقطه‌ها را واقعاً به آن‌جا ببریم:

\[ K(x, z) = \phi(x) \cdot \phi(z) \]

با عدد (کرنلِ چندجمله‌ای درجه‌ی ۲)، \(x = (1, 2)\) و \(z = (3, 4)\):

راهِ طولانی: اول \(\phi\)، بعد ضرب

\(\phi(v) = (v_1^2,\ \sqrt{2}\,v_1 v_2,\ v_2^2)\)
\(\phi(x) = (1,\ 2.83,\ 4)\)
\(\phi(z) = (9,\ 16.97,\ 16)\)
ضرب: \(9 + 48 + 64 = 121\)

راهِ کوتاه: کرنل

\(K(x, z) = (x \cdot z)^2\)
\(x \cdot z = 1 \cdot 3 + 2 \cdot 4 = 11\)
\(11^2 = 121\)
همان جواب، بدونِ ساختنِ \(\phi\).

با ۱۰۰۰ ویژگی، \(\phi\) درجه‌ی ۲ حدودِ نیم میلیون ستون دارد؛ ولی کرنل هنوز یک ضربِ داخلیِ ۱۰۰۰تایی و یک توان است.

کرنلِ RBF و پارامتر γ

پرکاربردترین کرنل، RBF (گاوسی) است. «شباهتِ» دو نقطه را از روی فاصله‌شان می‌دهد:

\[ K(x, z) = \exp\big(-\gamma\, \lVert x - z \rVert^2\big) \]
  • \(\lVert x - z \rVert^2\): مربعِ فاصله
  • \(\gamma\): شعاعِ اثرِ هر نقطه را تعیین می‌کند
  • \(K = 1\): دو نقطه یکی‌اند؛ \(K \to 0\): خیلی دور

γ بزرگ یعنی هر نقطه فقط همسایه‌های خیلی نزدیکش را «می‌بیند». مرز دورِ تک‌تکِ نقطه‌ها می‌پیچد. γ کوچک یعنی هر نقطه روی جای دور هم اثر دارد و مرز صاف می‌شود.

داده‌ی زیر حلقه‌ای است: یک دسته در وسط، دسته‌ی دیگر دورش، با هم‌پوشانی. ۸۰ نقطه‌ی آموزش و ۴۰۰ نقطه‌ی آزمون، C = ۱. γ را عوض کنید:

دسته‌ی بیرونیدسته‌ی وسطرنگِ پس‌زمینه = پیش‌بینیِ مدل

γ = ۰٫۰۱ (خیلی کوچک)

اثرِ هر نقطه تا دوردست می‌رسد و مدل عملاً خطی می‌شود؛ حلقه را نمی‌بیند و تقریباً همه‌جا یک دسته را می‌گوید. دقتِ آموزش ۵۶٫۳٪ و آزمون ۵۳٫۵٪؛ کم‌برازش.

γ = ۱ (متوسط)

مرز نرم است و دورِ دسته‌ی وسط را می‌گیرد. آموزش ۹۲٫۵٪، آزمون ۸۶٫۸٪، با ۴۱ بردار پشتیبان.

γ = ۱۰۰ (خیلی بزرگ)

دورِ تک‌تکِ نقطه‌ها جزیره می‌سازد. آموزش ۹۸٫۸٪ ولی آزمون فقط ۶۳٪، و هر ۸۰ نقطه بردار پشتیبان‌اند؛ بیش‌برازش.

C و γ را با هم تنظیم کنید (مثلاً جست‌وجوی شبکه‌ای روی ۰٫۰۱ تا ۱۰۰ برای هر دو). γ بزرگ و C بزرگ هر دو مرز را پیچیده‌تر می‌کنند.
کرنل‌های دیگر
  • خطی: \(K = x \cdot z\). برای متن و داده‌ی خیلی پرُبُعد معمولاً کافی و خیلی سریع است.
  • چندجمله‌ای: \(K = (\gamma\, x \cdot z + r)^d\). تعامل‌های تا درجه‌ی \(d\) بینِ ویژگی‌ها.
  • سیگموید: \(K = \tanh(\gamma\, x \cdot z + r)\). کم‌کاربرد.

هر تابعی کرنل نیست. ماتریسِ کرنل روی هر مجموعه نقطه باید مثبت نیمه‌معین باشد (شرطِ Mercer)، تا واقعاً ضربِ داخلی در یک فضا باشد.

کی SVM، کی نه؟

SVM خوب است وقتی…

  • داده کوچک یا متوسط است (تا چند ده هزار نمونه برای کرنل). مثلاً ۵۰۰۰ تصویرِ پزشکیِ برچسب‌خورده با ویژگی‌های دست‌ساز.
  • تعدادِ ویژگی‌ها زیاد است، حتی بیشتر از نمونه‌ها. مثلاً دسته‌بندیِ متن با TF-IDF و ۱۰۰ هزار کلمه: LinearSVC سریع و دقیق است.
  • مرزِ غیرخطی ولی صاف لازم است و نمی‌خواهید شبکه‌ی عصبی بسازید: SVM با RBF.

SVM خوب نیست وقتی…

  • داده خیلی بزرگ است. زمانِ آموزشِ SVC بینِ \(O(n^2)\) و \(O(n^3)\) رشد می‌کند. مثلاً ۱۰ میلیون کلیک: گرادیان بوستینگ یا رگرسیون لجستیک بهتر است.
  • احتمالِ خوش‌کالیبره لازم دارید. مثلاً «احتمالِ کلیک = ۰٫۰۳» برای قیمت‌گذاریِ تبلیغ. SVM فقط امتیاز می‌دهد.
  • داده‌ی خام مثلِ تصویر، صدا یا متنِ طولانی است. شبکه‌های عصبی خودشان ویژگی یاد می‌گیرند.
  • داده‌ی جدولیِ پر از ویژگیِ دسته‌ای و مقیاس‌های مختلف: درخت‌ها راحت‌ترند.

SVM در برابر رگرسیون لجستیک

هر دو یک خط \(w \cdot x + b\) یاد می‌گیرند. فرقشان در تابعِ خطا است:

SVM (خطی)

  • خطا: Hinge. نقطه‌های با \(m \ge 1\) اثر ندارند.
  • خط را فقط بردارهای پشتیبان می‌سازند.
  • خروجی: یک امتیاز، مثلاً \(f = 0.769\) برای ایمیلِ (۷، ۳). احتمال نیست.
  • هدف: بیشترین حاشیه.
  • با کرنل به‌راحتی غیرخطی می‌شود.

رگرسیون لجستیک

  • خطا: Log Loss. همه‌ی نقطه‌ها کمی اثر دارند.
  • خط را همه‌ی نقطه‌ها می‌سازند.
  • خروجی: احتمال، \(\sigma(0.769) = 0.68\).
  • هدف: بیشترین درست‌نمایی.
  • برای غیرخطی شدن باید ویژگی‌ها را دستی بسازید.

در عمل، روی داده‌ی جداشدنیِ خطی دقتِ این دو معمولاً خیلی نزدیک است. اگر احتمال لازم دارید، لجستیک. اگر حاشیه‌ی پهن و مقاومت در برابر نقطه‌های دور می‌خواهید، یا کرنل لازم دارید، SVM.

اگر از SVM احتمال بخواهیم؟

SVC(probability=True) یک رگرسیون لجستیکِ کوچک روی امتیازهای SVM آموزش می‌دهد (Platt Scaling) با اعتبارسنجیِ متقابلِ داخلی. کند است، و گاهی predict با بیشترین predict_proba یکی نیست. اگر فقط رتبه‌بندی لازم است، decision_function را استفاده کنید.

مقیاس‌بندی لازم است

SVM با فاصله کار می‌کند (پهنای خیابان، و در RBF مستقیماً \(\lVert x - z\rVert\)). اگر یک ویژگی عددهای بزرگ‌تری داشته باشد، همه‌چیز را او تعیین می‌کند.

با عدد: ویژگی‌ها = (تعدادِ لینک، طولِ ایمیل به کاراکتر):

  • ایمیلِ A: (۳، ۱۲۰۰)
  • ایمیلِ B: (۸، ۱۲۵۰). لینک‌ها خیلی فرق دارند.
  • ایمیلِ C: (۳، ۱۷۰۰). فقط کمی بلندتر.

بدونِ مقیاس‌بندی

فاصله‌ی A تا B: ۵۰٫۲، تا C: ۵۰۰. اختلافِ لینک فقط ۱٪ از مربعِ فاصله‌ی A تا B است (۲۵ از ۲۵۲۵). مدل لینک‌ها را عملاً نمی‌بیند.

بعد از استانداردسازی

با تقسیم بر انحرافِ معیار (لینک ÷ ۲٫۵، طول ÷ ۴۰۰): فاصله‌ی A تا B: ۲٫۰۰، تا C: ۱٫۲۵. حالا اختلافِ لینک دیده می‌شود.

همیشه قبل از SVM ویژگی‌ها را مقیاس‌بندی کنید (مثلاً StandardScaler)، و همان تبدیل را روی داده‌ی آزمون اعمال کنید. ساده‌ترین راه: یک Pipeline.

خوبی‌ها و بدی‌ها

خوبی‌ها

  • در فضای پرُبُعد خوب کار می‌کند.
  • بعد از آموزش فقط بردارهای پشتیبان لازم‌اند.
  • مسئله‌ی بهینه‌سازی محدب است: یک جوابِ بهینه‌ی سراسری، بدونِ گیر کردن در کمینه‌ی محلی.
  • با کرنل، مرزهای غیرخطی بدونِ ساختنِ دستیِ ویژگی.
  • نقطه‌های دور و درست روی جواب اثر ندارند.

بدی‌ها

  • روی داده‌ی بزرگ کند است (کرنل).
  • احتمال نمی‌دهد.
  • به مقیاسِ ویژگی‌ها حساس است.
  • C و γ باید با دقت تنظیم شوند.
  • تفسیرِ مدلِ کرنلی سخت است؛ وزنِ هر ویژگی معنیِ روشنی ندارد.
  • برای چند دسته باید چند مدلِ دودویی بسازد (یکی در برابرِ یکی، یا یکی در برابرِ بقیه).

کد

SVM خطی از صفر با NumPy (گرادیان‌کاهشی روی Hinge Loss):

import numpy as np

def fit_linear_svm(X, y, C=1.0, epochs=5000, lr=0.01):
    """y must be -1 / +1. Minimises 0.5*||w||^2 + C * sum(hinge)."""
    n, d = X.shape
    w, b = np.zeros(d), 0.0
    best = (np.inf, w, b)
    for t in range(1, epochs + 1):
        viol = y * (X @ w + b) < 1            # points with hinge > 0
        grad_w = w - C * (y[viol, None] * X[viol]).sum(axis=0)
        grad_b = -C * y[viol].sum()
        step = lr / np.sqrt(t)                 # shrinking step
        w = w - step * grad_w
        b = b - step * grad_b
        J = 0.5 * w @ w + C * np.maximum(0, 1 - y * (X @ w + b)).sum()
        if J < best[0]:                        # hinge is not smooth:
            best = (J, w, b)                   # keep the best point seen
    return best[1], best[2]

X = np.array([[1,2],[2,1],[2,3.5],[3,2],[1,4.5],[4,1],[0.5,0.5],
              [6,5],[7,7],[5,7],[8,4.5],[6.5,8.5],[9,8],[8.5,2.5]], float)
y = np.array([-1]*7 + [1]*7)
w, b = fit_linear_svm(X, y)
print(w, b, 2 / np.linalg.norm(w))   # ≈ [0.385 0.308] -2.85  4.06

گرادیانِ Hinge برای نقطه‌هایی که \(y f < 1\) دارند \(-y\,x\) است و برای بقیه صفر. چون Hinge در \(m = 1\) شکسته است، این «زیرگرادیان» است و بهترین نقطه‌ی دیده‌شده را نگه می‌داریم.

What is an SVM and what does it optimize?

A linear SVM finds the hyperplane \(w\cdot x + b = 0\) that separates the two classes with the largest margin. Points on the margin satisfy \(|w\cdot x + b| = 1\), so the margin width is \(2/\lVert w\rVert\). Maximising it is the same as solving \(\min \tfrac12\lVert w\rVert^2\) subject to \(y_i(w\cdot x_i + b)\ge 1\). Example: for 14 emails described by (links, ad words), the solution is \(w \approx (0.385, 0.308)\), \(b \approx -2.846\), \(\lVert w\rVert \approx 0.493\), so the street is \(2/0.493 \approx 4.06\) wide. Other lines that also separate all 14 points leave only 0.35 to 0.86 to the nearest point instead of 2.03. A wide margin leaves room for new points that are slightly off, which usually means better generalisation.

What are support vectors, and why does the model depend only on them?

Support vectors are the training points on the margin or inside it (or misclassified): the points with \(y_i f(x_i) \le 1\). In the dual solution \(w = \sum_i \alpha_i y_i x_i\), and \(\alpha_i = 0\) for every point strictly outside the margin, so only support vectors appear in \(f(x)\). Equivalently, the hinge loss is exactly zero for \(y f \ge 1\), so those points contribute no gradient. Example: in the demo, moving the spam email (9, 8) to (9.5, 6) leaves the line and the 4.06 width unchanged; moving the support vector (6, 5) to (5.5, 4.5) rotates the line and the width drops to 3.36. Only 3 of 14 points are needed for prediction.

What is the difference between hard margin and soft margin? What are slack variables?

Hard margin requires every point to be correctly classified and outside the margin; it has no solution if the data is not linearly separable, and a single outlier can drag the boundary. Soft margin adds a slack \(\xi_i \ge 0\) per point: \(y_i(w\cdot x_i+b) \ge 1-\xi_i\), and pays \(C\sum\xi_i\) in the objective. \(\xi_i = 0\): outside the margin; \(0<\xi_i\le 1\): inside the margin but correct; \(\xi_i>1\): misclassified. At the optimum \(\xi_i = \max(0, 1 - y_i f(x_i))\), which is the hinge loss.

What does the C parameter do?

C weights the total slack against the margin term \(\tfrac12\lVert w\rVert^2\); it is an inverse regularisation strength. Small C: violations are cheap, the margin is wide, some training points are misclassified, the model is simpler (higher bias, lower variance). Large C: violations are expensive, the model tries to classify every training point, the margin gets narrow (lower bias, higher variance). Example from the demo (16 emails including two unusual ones): C = 0.01 gives a 7.75-wide street with 2 errors and 14 support vectors; C = 100 gives 0 errors but a street only 0.67 wide with 3 support vectors. Tune C by cross-validation on a log scale.

What is the hinge loss? How does it compare with log loss?

With margin score \(m = y\,f(x)\): hinge \(= \max(0, 1-m)\); log loss \(= \ln(1+e^{-m})\). Numbers: at \(m=-1\) hinge 2 vs log 1.313; at \(m=0.5\): 0.5 vs 0.474; at \(m=1\): 0 vs 0.313; at \(m=2\): 0 vs 0.127. Hinge is exactly zero once a point is correct with margin 1, so far-away correct points have no influence (sparse solution, support vectors). Log loss never reaches zero, so every point matters a little, and its output maps to a probability through the sigmoid. Both grow linearly for very wrong points, so both are less sensitive to outliers than squared loss. The full linear SVM objective is \(\tfrac12\lVert w\rVert^2 + C\sum_i \max(0, 1-y_i(w\cdot x_i+b))\).

Explain the kernel trick.

In the dual problem and in the decision function, data appears only through inner products \(x_i\cdot x_j\). If we map data to a feature space \(\phi(x)\) where it is linearly separable, we only need \(\phi(x)\cdot\phi(z)\), and a kernel \(K(x,z)\) computes that directly without building \(\phi\). Example: 1-D points \(-1..1\) (class A) and \(\pm2.5, \pm3\) (class B) are not separable on a line; adding \(x^2\) makes them separable by \(x^2 = 3.6\). Numeric check for the degree-2 polynomial kernel with \(x=(1,2)\), \(z=(3,4)\): \(\phi(v) = (v_1^2, \sqrt2 v_1v_2, v_2^2)\) gives \(9+48+64 = 121\), and \(K = (x\cdot z)^2 = 11^2 = 121\). A valid kernel must give a positive semi-definite Gram matrix (Mercer's condition).

What is the RBF kernel and what does gamma control?

\(K(x,z) = \exp(-\gamma\lVert x-z\rVert^2)\): similarity that decays with distance. Gamma sets how far one training point's influence reaches. For two points 0.5 apart, \(K = 0.975\) at \(\gamma = 0.1\) but \(0.082\) at \(\gamma = 10\). Large gamma: tiny radius, boundary wraps around individual points, overfitting; in the ring demo, \(\gamma = 100\) gives 98.8% train but 63% test accuracy with every point a support vector. Small gamma: very smooth, nearly linear boundary, underfitting; \(\gamma = 0.01\) gives about 54% test. \(\gamma = 1\) gives 86.8% test. Tune C and gamma together with a log-spaced grid search.

scikit-learn user guide (parameters C and gamma)

Why must you scale features before training an SVM?

The margin and the RBF kernel are based on Euclidean distance, so a feature with a large range dominates. Example: emails as (links, characters): A = (3, 1200), B = (8, 1250), C = (3, 1700). Unscaled, A–B distance is 50.2 and A–C is 500; the 5-link difference is only 25 of the 2525 squared distance (1%). After dividing by the standard deviations (2.5 links, 400 characters), A–B is 2.00 and A–C is 1.25, so links matter again. Fit the scaler on training data only and apply the same transform to test data (a Pipeline does this).

scikit-learn user guide (tips on practical use)

SVM vs logistic regression: when would you use which?

Both learn a linear score \(w\cdot x+b\); the difference is the loss. SVM uses hinge loss (sparse, only support vectors matter, maximises the margin) and outputs a score, not a probability. Logistic regression uses log loss (every point contributes) and outputs calibrated-ish probabilities: a score of 0.769 becomes \(\sigma(0.769) = 0.68\). Choose logistic regression when you need probabilities (ranking ads by click probability, risk thresholds) or very large data; choose SVM when you want a non-linear kernel on small or medium data, or a robust margin in high dimensions (e.g. text with a linear SVM). On linearly separable problems their accuracy is often very similar.

How does SVM training scale? When is it a bad choice?

Kernel SVC (libsvm) costs between \(O(d\,n^2)\) and \(O(d\,n^3)\) time and needs the kernel matrix entries, so it becomes impractical beyond tens or hundreds of thousands of samples. LinearSVC (liblinear) scales almost linearly in the number of samples and features, so it is fine for millions of sparse text documents. Prediction cost of a kernel SVM grows with the number of support vectors. Bad choices: very large datasets with a kernel, problems that need probabilities, raw images/audio where deep networks learn better features, and messy tabular data where gradient-boosted trees usually win.

scikit-learn user guide (complexity); PracHub (SVM kernels and complexity)

Can an SVM output probabilities?

Not directly: it outputs the signed distance \(f(x)\). Scikit-learn's SVC(probability=True) uses Platt scaling: it fits a logistic regression \(p = \sigma(A f(x) + B)\) on the SVM scores using an internal 5-fold cross-validation. This is slow on large data, and the probabilities can be inconsistent with predict (the predicted class can have probability below 0.5). If you only need a ranking, use decision_function; for calibration of any model, CalibratedClassifierCV.

scikit-learn user guide (scores and probabilities)

How does SVM handle more than two classes?

SVM is a binary classifier, so multi-class problems are split into binary ones. One-vs-rest: K classifiers, each class against all others; predict the class with the highest score (LinearSVC does this). One-vs-one: K(K−1)/2 classifiers, one per pair, and a vote (SVC does this internally; with 10 classes that is 45 classifiers, each trained on only two classes' data, which is cheap for a kernel SVM whose cost grows faster than linearly in n). For imbalanced classes, use class_weight="balanced", which scales C per class.
